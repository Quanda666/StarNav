# AI 小助理使用与配置指南

本文说明星漫旅站 AI 小助理（前台悬浮面板）与后台 AI 能力的工作方式、可达到的准确度边界，以及联网搜索的配置方法。

---

## 一、设计原则：能算的不问模型

大模型擅长表达，不擅长记事实。因此助手把问题分成四类，**事实类问题一律不经过模型**：

| 问题类型 | 例子 | 处理方式 | 准确率 |
|---|---|---|---|
| 时间 / 日期 / 星期 | 「今天星期几」「现在几点」 | 服务端按北京时间直接计算 | 100% |
| 站点统计 | 「本站有多少书签」「有多少个标签」「今天新增多少」 | 直接聚合查询 D1 | 100% |
| 站内事实（找书签 / 分类 / 链接 / 列表） | 「图床类的有哪些」「X 在哪个分类」 | 站内检索 + 规则化作答 | 100%（受收录数据决定） |
| 开放问答 / 建议 / 站外信息 | 「推荐几个 AI 站点」「帮我看看这个链接」 | 检索结果 + 联网结果 + 大模型 | 取决于检索与配置 |

好处有两个：**答案不会胡说**，而且这些问法**不消耗 token**（未配置模型的站点同样能回答）。

---

## 二、站内检索是怎么变准的

一次提问会走「检索计划 → 多路召回 → 加权排序」：

1. **识别站内词汇**：把提问里出现的**标签名**和**分类名**识别成精确条件（`tag:"AI"`、`cat:"设计素材"`），命中标签/分类的书签天然更相关。
2. **多路召回**：
   - 原句优先（权重 3.0，precision 最高）；
   - 标签匹配（2.6）、分类匹配（2.4）；
   - 关键词扩展（含「云盘 / 图床 / AI」等同义词表与站内标签词汇）。
3. **加权累加排序**：命中越多路、越「独有」的关键词权重越高（命中数少的词更具区分度），再叠加站内热度（`hits`）对数加权。
4. **多轮上下文**：最近 8 条对话会一起送给模型，因此「它 / 这个 / 刚才那个」能正确指向上一轮的书签。

> 检索由站点的真实标签体系驱动：标签越规范，助手的答案越准。可以先用后台「AI 分析 → 无标签书签」补齐标签。

## 三、注入给模型的上下文

调用大模型时，除检索结果外还会注入：

- **当前北京时间**（`2026年10月30日 星期五 15:30`）——避免模型用训练数据里的旧日期回答；
- **站点规模快照**（书签数 / 分类数 / 标签数 / 今日与近 30 天新增 / 最热分类与标签 / 待审数）；
- **联网检索结果**（如有，明确标注「非本站书签」并要求按 `[1][2]` 标注来源）；
- **用户贴出的链接的实时抓取内容**（标题 / 描述 / 正文节选）。

并且有硬约束提示词：本站检索结果是唯一可信来源，不得编造不存在的书签/分类/标签/URL。

## 四、联网搜索配置

联网是**可选能力**，不配置时助手只用站内数据，功能不受影响。

后台路径：**AI 接口 → 联网搜索**。

| 后端 | 需要 Key | 说明 |
|---|---|---|
| Tavily | 是 | 推荐，专为 LLM 设计，直接返回摘要，免费额度够个人站点 |
| Serper | 是 | Google 结果，速度快 |
| Brave Search API | 是 | 有免费额度 |
| SearXNG | 否 | 自建实例，填实例地址即可（需允许 JSON 输出） |
| DuckDuckGo | 否 | 免 Key 兜底，可能被限流或被拦截，仅作应急 |

可选项：

- **站内无结果时自动联网补充**：站内检索为空时自动联网，避免答「不知道」；
- **单次结果数**：默认 5 条，会一并注入模型并要求标注来源。

前台使用：AI 面板右上角「🌐 联网」按钮。开启后本次会话的提问会允许联网检索（状态记在本机浏览器）。

触发优先级：用户手动开启 > 提问里含「联网 / 网上 / 最新」等词 > 自动模式兜底 > 不联网。

排错：配置页的「测试搜索」会真实发起一次检索并显示耗时与样例结果；失败时给出具体错误（如 Key 无效、被限流）。

## 五、标签自动生成

后台「书签 → AI 推荐标签」/「标签 → 批量 AI 预览」，以及前台「添加书签 → 🏷️」，都使用同一套引擎：

**四条信号加权打分**

1. **站内词汇表**：已有标签出现在名称（95 分）/描述（72）/域名（66）/分类同名（40）；
2. **分类共识**：同分类下 ≥20% 书签使用的标签直接进入候选（体现站内习惯）；
3. **语义词典**：25 组常见站点类型关键词（AI、图床、网盘、代码托管……），库还空时权重更高；
4. **域名规则**：如 `github.com → 代码托管`、`figma.com → 设计素材`。

**再叠加**：标签热度对数加权、分类共现比例加权、书签已有标签保留（不丢人工成果）。

**结果清洗**：与分类名相同的标签会被剔除（分类已表达该信息）、与书签名相同的不输出、大小写归一到站内既有写法、长度限制 2–12 字。

后台预览里把鼠标悬停在标签上可以看到**推荐理由与匹配度**，便于人工快速判断。

## 六、相关设置项

| 设置 | 位置 | 说明 |
|---|---|---|
| 启用大语言模型回复 | AI 接口 | 关闭后助手仍可回答时间/统计/站内检索类问题 |
| 接口地址 / 模型 / Key | AI 接口 | 任意 OpenAI 兼容接口（官方、中转均可） |
| 系统提示词 | AI 接口 | 可覆盖默认人设与规则 |
| 联网搜索 | AI 接口 → 联网搜索 | 见上文 |
| 标签推荐 | 无需配置 | 未配置模型时走「站内词汇表 + 规则」 |
